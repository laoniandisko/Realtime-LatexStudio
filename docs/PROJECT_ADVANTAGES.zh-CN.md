# 项目优势与性能说明

SideX LaTeX Studio 将项目管理、TeX 源码、真实排版输出和项目智能体放在一个本地工作流中。它适合希望保留 LaTeX 模板与源码控制，同时减少“修改—等待整篇编译—查找位置”往返的写作场景。

## 主要优势

| 优势 | 已实现的行为 | 实际意义 |
| --- | --- | --- |
| 从项目主页开始 | 新建、导入、搜索、排序、改显示名、归档与恢复 | 一个入口管理多个本地论文目录 |
| 项目会话隔离 | 每个项目独立文件根、令牌、实时引擎、终端和智能体任务 | 同时打开不同项目时不会把旧页面保存到新项目 |
| 页面原位修改 | 正文在页面中放光标、选字、整段编辑、撤销并回写源码 | 保持写作位置，减少来回寻找源码 |
| TeX 仍负责排版 | 字形与坐标来自 TeX；完整 PDF 负责分页、引用和浮动体 | 保留模板工作流，不用浏览器样式重建最终论文 |
| 交互优先 | 首次输入立即下发，后续输入合并，Worker 只保留最新待处理快照 | 减少固定等待与过期任务积压 |
| 图表操作完整 | 图表整体移动，八方向尺寸柄，保留 caption/label | 调整时不把题注和引用从对象拆开 |
| 自选模型 | API 自动发现模型、图片粘贴、项目文件工具与差异记录 | 模型服务可替换，配置不绑定单一供应商 |
| 本地优先、结构集中 | 浏览器前端加本机 Node 服务，移除上游桌面与扩展平台构建 | 便于阅读、调试和二次开发 |

项目主页借鉴常见在线 LaTeX 编辑器的项目列表方式，但项目文件保存在本机目录；当前没有多人协同、云端同步或托管服务功能。

## 保持正确性的优化

优化没有通过移除排版保护来缩短表面耗时。局部覆盖层仍检查原页、栏、行槽、邻段碰撞与版本顺序；不安全的结果等待完整排版，保留上一份有效 PDF。

已实现的主要优化包括：

- 空闲时直接下发首个输入，持续输入仍限制在一个文档请求在途并合并最新内容。
- 源码映射批量转换 UTF-8 端点，避免对每个 span 重复编码全文。
- 分析队列只保留同一单元最新排队快照，取消结果不会与其他源码版本混用。
- 缓存原排版的静态边界，新增覆盖层和相互碰撞仍动态检查。
- 显式完整排版不再额外等待 300ms，自动更新仍在输入停顿后合并确认。
- 在官方运行时的兼容副本中修复引用宏分词与矩阵指令编码问题，不修改官方 DLL、论文源文件或 TeX 节点。

## 测量结果如何理解

以下是开发机 Intel Core i5-14600K、20 个逻辑处理器上的本地观测。不同文档、字体、宏包、硬件和系统负载会改变结果。

| 指标 | 优化前 | 优化后 | 范围 |
| --- | ---: | ---: | --- |
| 首次文档请求下发 | 12.25ms | 0.51ms | 单页控制器对照；不含浏览器绘制 |
| 14,548 字符、22 spans 的源码映射 | 0.849ms | 0.0286ms | 每包中位数 |
| 35 行段落的覆盖层安全检查 | 0.275ms | 0.0766ms | 单次检查中位数，判断结果相同 |
| 同单元 1001 次分析请求的 Worker 派发数 | 1001 | 2 | 任务数，不是端到端延迟 |
| 一份 9 页文档完整排版至后端 PDF 可用 | 1156ms | 781ms | 各 6 次热运行中位数，不含 PDF 读取与浏览器绘制 |

普通局部 TeX 更新在测试中常见约 0.7–4ms；复杂段落可能更慢，也可能因安全检查进入完整排版。9 页案例使用了未随仓库发布的私有输入，属于开发观测，不是可由本仓库重现的公开基准，也不代表所有论文的性能。

可使用仓库中的通用示例和集成测试验证自己的环境：

~~~sh
npm run test:session
npm run test:page-tools
npm run test:host
~~~

测试输出区分局部引擎耗时、控制器请求和后台完整排版。页面中的引擎毫秒值不能直接解释为“按键到屏幕”的全部延迟，整篇完整编译也没有达到或承诺 1ms。

## 当前能力边界

- 页面编辑依赖可验证的源码映射；宏生成内容和歧义范围保留源码入口。
- 公式目前使用 LaTeX 表达式输入，不是可视化符号光标编辑器。
- 图表移动的最终页、栏和位置仍由模板的浮动排版规则决定。
- 不同 TeX 引擎可能产生不同断行与分页，投稿前应使用指定引擎检查输出。
- 运行时版本固定为 0.0.6，兼容副本经过原生回归；升级引擎需要重新验证。
- 智能体会把相关上下文发送到配置的 API，是否启用及使用哪个服务由用户选择。

这些边界决定了本项目的目标：提供有源码依据、能持续输入、能回到权威 TeX 输出的本地交互写作工具。
